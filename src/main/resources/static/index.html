Support agents

An agent is a login for the Conversations queue. Add teammates here, then hand tickets to them from the Agent column. Usernames are globally unique — if one is taken, the hub issues a variant and the add result shows the exact name to sign in with. Passwords are stored only as BCrypt hashes. Press Remove on a row to take away that login and nothing else: their tickets return to the queue, and the project, its keys and its trained knowledge stay. Admin rows carry a Protected note instead of a button — this dashboard never removes an admin, so a project always keeps someone who can manage it. 1 · Get your project's keys

Every application that embeds the support bot is registered as a client (project) with its own credentials. The API key is shown only once, at onboarding.

  1. Open Clients and enter the project name — the hub generates a unique client key and a strong API key.
  2. Copy both values from the credential ticket and store them in your application's environment (for example SUPPORT_CLIENT_KEY and SUPPORT_API_KEY).

Lost the API key? It can't be recovered — but Clients → Rotate key issues a new one for the same project, so nothing needs re-training. The old key stops working the moment you rotate.

2 · Call the chat API

Send two headers with every request from your application. Never expose the API key in browser code — proxy through your backend.

curl -X POST http://localhost:8000/api/v1/support/chat \
  -H "Content-Type: application/json" \
  -H "X-Client-Key: <your-client-key>" \
  -H "X-API-Key: <your-api-key>" \
  -d '{"customerId":"user-123","message":"What is the return policy?"}'
customerId

Your user's id. A conversation is created on first message.

conversationId

Optional. Send the id from the reply to continue the same conversation.

message

The customer's question.

Reply: {"conversationId":"…","status":"AI_HANDLING","response":"…"} — keep conversationId for follow-ups.

3 · Train your project's knowledge

The bot only answers from knowledge trained for your project. Upload it the same way — with your project's keys.

curl -X POST http://localhost:8000/api/v1/knowledge \
  -H "Content-Type: application/json" \
  -H "X-Client-Key: <your-client-key>" \
  -H "X-API-Key: <your-api-key>" \
  -d '{"name":"return-policy","category":"policies","version":"1.0","content":"Customers may return eligible items within 30 days."}'

Files: POST /api/v1/knowledge/file as multipart/form-data with a file field — PDF and Markdown only. Agents can also train any project from the Knowledge screen.

How this hub is built

Java 27 on Spring Boot 4.1 with Spring AI 2.0 — Gemini answers grounded in each project’s own documents, retrieved from an Oracle vector store. Two credential realms keep tenants apart: agent JWTs for this console, client key + API key hashes for embedded bots. The console itself is a dependency-free SPA; the routing core you see in the sidebar is Three.js r180, vendored locally.
