Registered projects

API keys are stored only as hashes, so they appear nowhere in this list — each was revealed once on its credential ticket. Lost one? Press Rotate key on the row: the project gets a fresh API secret while its client key, id and all trained knowledge stay exactly as they are.

Support agents

An agent is a login for the Conversations queue. Add teammates here, then hand tickets to them from the Agent column. Usernames are globally unique — if one is taken, the hub issues a variant and the add result shows the exact name to sign in with. Passwords are stored only as BCrypt hashes. Press Remove on a row to take away that login and nothing else: their tickets return to the queue, and the project, its keys and its trained knowledge stay. Admin rows carry a Protected note instead of a button — this dashboard never removes an admin, so a project always keeps someone who can manage it. Your own account shows Signed in and cannot be removed either.

1 · Get your project's keys

Every application that embeds the support bot is registered as a client with its own credentials.

  1. Open Clients and create a project.
  2. Copy the generated client key and API key.
  3. Store both credentials securely in your backend environment.

Lost the API key? Use Clients → Rotate key to generate a replacement. The old key stops working after rotation.

2 · API base URL

Automatically detected from the current dashboard address. All endpoints below use this base URL.

Detecting base URL...

If the API runs on another host or port, configure its URL in the JavaScript configuration instead.

3 · Start a customer conversation

Send both client authentication headers. Never expose the API key in browser-side production code.

Required body fields: customerId and message. The server creates a conversation when no conversation ID is supplied.

Example response:

{
  "conversationId": "generated-uuid",
  "status": "AI_HANDLING",
  "response": "Customers may return eligible books within 30 days..."
}

4 · Continue the same conversation

Reuse the conversation ID returned by the first message. Send another message to continue the conversation history.

The conversation ID must belong to the authenticated client. Otherwise, the service returns a conversation-not-found error.

5 · Ingest knowledge using client credentials

Add project-specific text knowledge for the support bot.

The request stores knowledge metadata and creates vector embeddings in the Oracle vector store.

6 · Upload a knowledge file

Upload a PDF or Markdown file using multipart form data. Do not manually set the Content-Type header when using curl's -F option.

Required field: file. Optional fields: name, category, and version. Supported extensions: PDF, MD, and Markdown.

7 · List conversations as an agent

Requires an agent JWT obtained through your existing agent login endpoint.

The authenticated agent's tenant is determined from the signed JWT.

8 · List clients as an agent

Returns client records, including their IDs, names, keys, active status, and timestamps. API secrets and hashes are not returned. Save a client ID to manage its knowledge.

9 · List knowledge for a client

Requires an agent JWT and a valid client ID.

10 · Ingest knowledge as an agent

Train a selected project using an agent JWT instead of client API credentials.

11 · Upload knowledge as an agent

Use multipart form data with the required file field and optional name, category, and version fields.

How this hub is built

Java 27 on Spring Boot 4.1 with Spring AI 2.0 — Gemini answers grounded in each project’s own documents, retrieved from an Oracle vector store. Two credential realms keep tenants apart: agent JWTs for this console, client key + API key hashes for embedded bots. The console itself is a dependency-free SPA; the routing core you see in the sidebar is Three.js r180, vendored locally.
